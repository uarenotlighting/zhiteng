# 知疼 App 前端开发前置规范

> 本文件是本目录的强制前置文档。收到任何 App 需求后，先完整阅读本文件与相关产品文档，再动手改代码。

## 1. 项目与技术基线

- 产品：知疼——疼痛记录与就医沟通工具。
- 端形态：iOS / Android 原生壳，Flutter 共用业务层。
- 目录：与 `zhiteng_miniPrograme`、`zhiteng_server` 平级，独立工程 `zhiteng_app`。
- 数据：与小程序共用 `PainEntry` 模型与后端口径；本地优先 SQLite，云同步后置。
- 人体模型：采用 BodyParts3D / Z-Anatomy 许可白名单资产维护同一套 Blender 母版；App 正式同时提供同源 2D 正交预渲染与 3D GLB/glTF + raycasting；共享目录 `../zhiteng_body3d`；记录保存 `bodyModelVersion`。
- 产品不是医疗诊断工具，不得暗示已诊断病因或给出具体药物建议。

### 1.1 与小程序的边界

| 端 | 职责 |
|---|---|
| 小程序 | 首版仅提供同源真实人体 2D 定位、近期历史和单次摘要；3D 设计保留到后期版本，不进入首版包体 |
| App | 正式同时提供 2D + 3D 定位，并承担无限历史、趋势、用药、批量 PDF、同步和 Watch |

App 吸引力来自能力增量，不得依赖「小程序故意做残」导流。

### 1.2 视觉与交互参考

界面气质对齐品牌文档，并参考「疼痛坐标」公开演示的定位交互：

- 浅灰页面底、近黑主操作、鲜红疼痛标记。
- 大面积人体舞台 + CAD 十字准星拖动定位。
- 表面 / 肌肉 / 骨骼等分层与体内半透明表达。
- 部位快捷切换、点/片/线/放射标记形态。
- 导出给医生是核心价值，不是装饰入口。

## 3. 推荐开发顺序

1. 账号与小程序数据读取 / 迁移就绪。
2. 在同一正式版本完成同源 2D + 3D 定位记录，并打通坐标迁移和历史数据。
3. 高级历史、报告、语音、用药。
4. 继续优化 3D 分层、剖切、加载速度和低性能设备体验。
5. Apple Watch（原生 watchOS，不复制完整表单）。

## 4. 工程约定

- 业务代码放在 `lib/`，按 `core` / `data` / `state` / `features` / `widgets` 分层。
- 平台差异（健康数据、WatchConnectivity、文件系统）集中在适配层，不散落在页面。
- 使用 `flutter analyze`；不为演示硬编码诊断文案。
- 人体模型第三方许可必须保留署名（见 `ATTRIBUTION.md`）。
