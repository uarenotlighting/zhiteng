# 产品定位与竞争差异

## 核心定位

> 把说不清的疼痛，变成可以看见、回顾并向医生说明的身体时间线。

产品不是疾病诊断工具，也不只是疼痛备忘录。虚拟人体帮助用户寻找和表达位置，结构化记录帮助用户理解变化并完成就医沟通。

## 核心产品原则

1. 不要求用户知道准确的医学部位。
2. 允许大概位置、范围、不确定、扩散和牵连。
3. 在疼痛发作状态下，仍能用数秒完成记录。
4. 先记录最少信息，恢复后可以补充。
5. 记录最终要形成时间线、趋势和医生摘要。
6. 产品只表达用户记录的事实，不自动诊断病因。

## 与「疼痛坐标」的关系

两款产品共享“把身体感觉投射到虚拟人体”的思想，但产品深度不同。

| 维度 | 疼痛坐标 | 本产品 |
|---|---|---|
| 主要定位 | 3D 疼痛位置定位工具 | 疼痛记录与就医沟通系统 |
| 核心问题 | 疼痛在哪里 | 哪里痛、怎么痛、多久、如何变化、采取了什么措施 |
| 主要表现 | 3D 人体、准星、摇杆、红点 | 小程序使用真实人体 2D 身体地图，App 同时提供同源 2D＋3D |
| 位置表达 | 空间坐标点 | 点、范围、多位置、深度、不确定、扩散和牵连 |
| 时间表达 | 单次位置记录为主 | 开始、进行中、变化、结束、补记 |
| 长期价值 | 保存和导出 | 日历、趋势、用药效果、医生摘要、跨端数据 |

## 产品表达差异

「疼痛坐标」更接近一台医学定位仪，本产品更接近个人身体感受地图。

```text
疼痛坐标
= 虚拟人体＋疼痛坐标

本产品
= 虚拟人体
+ 疼痛事件
+ 发作时间线
+ 用药与缓解记录
+ 趋势分析
+ 医生沟通报告
+ 跨平台与穿戴设备
```

## 视觉方向

- 平静、低刺激、可信任。
- 身体图是首屏主体，不是表单中的小图标。
- 默认使用同一 Blender 母版导出的中性真实人体，不使用简笔画，也不强化性别特征。
- 普通界面使用柔和中性色，疼痛强度才使用黄、橙、红。
- 暗夜模式降低发作时的视觉刺激。
- 文案采用自然语言，不要求用户理解专业疼痛术语。

关键提示语：

> 不需要知道准确部位，先在身体上找找看。
