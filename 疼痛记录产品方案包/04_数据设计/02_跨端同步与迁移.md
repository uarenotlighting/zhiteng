# 跨端同步与迁移

## 基本原则

- 微信、抖音、小红书、App 使用同一业务数据结构。
- 平台用户 ID 不能直接作为跨平台唯一身份。
- 小程序 V1 允许游客浏览，但创建和保存记录前必须登录。
- 小程序 V1 使用平台身份登录，业务数据归属于后端生成的内部 `user_id`。
- V1 暂不提供跨平台统一账号绑定和跨设备统一登录，但数据模型必须预留能力。
- 健康数据同步必须取得明确同意。

## 游客模式

- 允许浏览产品介绍、示例和新手引导。
- 不允许创建、修改或保存疼痛记录。
- 尝试使用记录、历史、趋势或摘要时，引导完成平台登录。

## 小程序 V1 数据保存

- 登录后的健康记录上传并保存在服务端。
- 本地存储只作为必要缓存，不作为唯一数据源。
- 用户清理小程序缓存后，使用同一平台身份重新登录，应从服务端恢复数据，不视为数据丢失。
- 清理本地缓存不能替代用户主动删除健康数据。

## 统一账号

```text
UnifiedAccount
  id
  phone/email/passkey
  platformBindings[]
    platform
    platformUserId
    boundAt
```

每个平台身份只是一个登录凭证，业务数据归属于统一账号。

小程序 V1 实现时建议拆分为：

```text
User
  id: 内部 user_id

PlatformIdentity
  id
  userId
  platform: weixin/douyin/xiaohongshu
  platformUserId
  boundAt
```

多个 `PlatformIdentity` 可以在后续版本绑定到同一个内部 `user_id`，但必须通过可验证的账号绑定流程完成。不能把客户端提供的 `user_id` 当作身份凭证，也不能仅根据昵称、手机号明文或相似资料自动合并。

V1 中每个平台身份默认形成独立登录关系，不提供用户可见的跨平台合并入口。

## 小程序到 App

按平台允许能力选择：

1. 登录相同统一账号。
2. 一次性迁移码。
3. 用户主动导出加密文件，再导入 App。

不能依赖把敏感数据静默写入剪贴板，也不能把下载 App 设为完成小程序流程的前置条件。

## 同步冲突

- 每条记录使用全局 UUID。
- 保存 `updatedAt` 和 `syncVersion`。
- 追加型时间线事件优先合并，而不是整条覆盖。
- 删除使用可同步的 tombstone，避免记录在其他设备重新出现。
- 同一字段发生冲突时保留两个版本，提示用户确认。

## Watch 同步

- Watch 创建轻量时间线事件。
- 手机端收到后合并进 `PainEntry`。
- Watch 更新不得覆盖手机端的详细位置和备注。
- 网络恢复后按事件 ID 去重。
