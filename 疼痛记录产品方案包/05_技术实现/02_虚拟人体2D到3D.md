# 虚拟人体：2D 到 3D

## 2D 真实人体实现（App 与小程序共用）

2D 模式不再使用简笔画或另外手绘的 SVG 人体。它必须使用与 3D 模式相同的 Blender 母版，以正交相机预渲染出真实人体比例的2D图像。

2D 是 App 和小程序都必须提供的正式记录模式，不是小程序专属的降级备用：

- App：用于快速记录、历史总览、热力图，以及用户不想操作3D时的简化入口。
- 小程序：第一版只上线2D，用于最低摩擦的快速记录。轻量3D的文档、坐标和资产方案保留，后续版本再开发，不作为小程序首版的入口、包体或验收要求。
- 两端使用相同图像、蒙版、区域映射、坐标定义和版本号。

每次模型导出同时生成：

```text
export/2d/
  front.webp
  back.webp
  left.webp
  right.webp
  front-mask.png
  back-mask.png
  left-mask.png
  right-mask.png
  regions.json
```

- 展示图使用 WebP，保留真实轮廓、轻微肌肉/关节结构与性别中性化材质。
- 正面、背面、左侧、右侧使用固定正交相机，不得手工拉伸或二次重绘。
- 蒙版图不显示给用户；不同颜色/ID 对应稳定的 `bodyPartId`，用于点击命中、左右判定和历史热力图。
- `regions.json` 记录蒙版 ID、身体区域和3D mesh 集合的映射。
- 首版可只发布正面和背面，但导出管线保留四视图。

每个区域继续使用稳定 ID：

```text
head
neck
left_shoulder
right_shoulder
chest
abdomen
lower_back
left_knee
right_knee
...
```

### 局部关注区域

不为每个部位重复绘图，而是对同一张高分辨率正交渲染图调整裁切框：

- 全身：完整 viewBox。
- 头颈：裁切头部和颈部。
- 肩臂：裁切肩膀、上臂和肘部。
- 右膝：裁切右腿膝关节。

疼痛位置使用相对整个人体图像的归一化坐标，因此局部标记可以回到全身总览。裁切框必须写入版本化配置，不得把局部坐标直接当作全身坐标。

### 2D 深度表达

2D 无法确定体内具体 Z 坐标，但不能强迫用户把深部疼痛标成表面疼痛：

| 用户选项 | `depthState` | 2D 标记样式 | 含义 |
|---|---|---|---|
| 皮肤 | `surface` | 清晰实心红点/区域 | 用户认为位置在皮肤层 |
| 肌肉 | `internal_unknown` | 深色中心＋模糊光晕 | 用户主观选择肌肉层，但没有精确 Z |
| 骨骼 | `internal_unknown` | 深色中心＋模糊光晕 | 用户主观选择骨骼层，但没有精确 Z |
| 说不清楚 | `unknown` | 半透明/虚线圈 | 不对层次或深度做假设 |

2D 的肌肉与骨骼是用户对疼痛层次的主观标注，不是诊断；`internal_unknown` 表示仍没有精确深度，不允许生成伪精确的 3D 坐标。

## 身体区域邻接图

建立区域之间的邻接关系：

```text
head <-> neck
neck <-> shoulders <-> upper_back
shoulder <-> upper_arm <-> elbow <-> forearm <-> hand
lower_back <-> hip <-> thigh <-> knee <-> lower_leg <-> foot
chest <-> abdomen <-> pelvis
```

用于：

- 自动建议关注区域组合。
- 识别连续扩散路径。
- 决定局部图裁切范围。
- 未来映射到 3D mesh。

## 2D 数据

除 `bodyPartId` 外，还应保存：

- `coordinateMode: 2d`
- `normalizedX/Y`
- `radius` 或涂抹 mask
- `side`
- `view: front/back/left/right`
- `layer: skin/muscle/bone/unknown`
- `depthState: surface/internal_unknown/unknown`
- `certainty`
- `bodyModelVersion`
- `coordinateSystemVersion`

## 3D 模型选型决策（2026-09-21）

正式方案不从零手工雕刻人体，也不直接搬运竞品未开源资产。统一采用 **BodyParts3D / Z-Anatomy 开源医学人体数据作为上游，由项目自己维护 Blender 改制与导出管线**。

参考工程：

- [`hpfrei/body-anatomy-3d-viewer`](https://github.com/hpfrei/body-anatomy-3d-viewer)：Z-Anatomy 的 Web GLB 简化、结构元数据、Three.js 加载与 raycast；适合作为 App 初始资产参考，不原样塞入小程序。
- [`yamz8/human-body-simulator`](https://github.com/yamz8/human-body-simulator)：参考皮肤、骨骼、器官分层，透明度与本地 Draco 加载。
- [`DrMuratAltun/anatomi-simulatoru`](https://github.com/DrMuratAltun/anatomi-simulatoru)：参考 Blender 批量导出、网格合批与 `structureId` 精确点选。

不选择「从球体、圆柱从零手搓人体」，原因是人体比例、关节、手部、面部与内部解剖结构的成本过高，且难以维持 App / 小程序坐标一致。

### 同源三类产物

App 3D、后续小程序 3D 与两端共用的2D图必须从同一 Blender 母版、同一上游版本导出，不再各自使用不同人体。

| 端 | 用途 | 建议资产 | 目标预算 |
|---|---|---|---|
| App | 完整3D定位与分层查看 | 连续皮肤壳＋浅表肌肉＋骨骼＋按需主要器官 | 优先保证模型与四层功能完整，全部本地打包，不设固定体积上限 |
| 小程序后续版 | 本地轻量3D定位（首版不上线） | 低模透明皮肤壳＋浅表肌肉，不带完整器官层 | 模型 700–900 KB；定位分包总体不高于 1.8 MB |
| App＋小程序2D | 快速记录、历史总览、热力图 | 正交 WebP＋不可见区域蒙版＋映射 JSON | 正背两视图 100–250 KB；四视图 200–500 KB |

三类产物必须共享：

- 相同的原点、比例、朝向与站姿。
- 相同的 `bodyModelVersion`、坐标迁移规则与固定正交相机配置。
- 稳定的 mesh / structure ID 映射；Mini LOD 可合并网格，但不得破坏区域和坐标对应。
- 同一份上游许可、署名、修改说明与导出清单。

### 要复现的交互效果

视觉与交互目标参考「疼痛坐标」公开演示，但代码和资产独立实现：

1. CAD 式十字准星确定屏幕 X/Y。
2. 通过摇杆或深度滑杆沿 ray 进入人体，得到真实模型空间 XYZ，不把深度固定为「表面」。
3. 红点必须是 WebGL 场景内的3D对象，不得使用永远浮在 Canvas 上方的 CSS 点作为正式实现。
4. 使用皮肤壳的 `depthTest` / `depthWrite` / `renderOrder` 表达表面点与体内点遮挡。
5. 支持点状、片状、线状、放射状，但所有表达都是「用户自报的大致位置」，不宣称医学精度。

## 3D 实现（Blender 正式管线）

人体 mesh **统一从已核验的 BodyParts3D / Z-Anatomy 结构导入 Blender，改制后导出**，工程内共享目录：`../../zhiteng_body3d/`（与 App、小程序平级）。

- 在 Blender 中按 Collection 分层：`ZT_Skin` / `ZT_Muscle` / `ZT_Bone` / `ZT_Organ`。
- 导出低模 GLB（`scripts/export_layers.py`），写入 `export/manifest.json` 的 `bodyModelVersion`。
- 运行时用 Three.js（或同类）加载 GLB，通过 raycasting 得到 meshId、面片、局部坐标或 UV。
- 为关注区域准备相机预设，而不是切割多套人体模型。
- 头颈关注区域自动将摄像机移动到头颈；膝盖关注区域自动移动到膝关节。
- 皮肤层始终加载和显示，不在界面中设置单独开关；肌肉、骨骼、主要器官三者单选，分别形成「皮肤＋肌肉」、「皮肤＋骨骼」、「皮肤＋器官」的组合显示。
- 运行时引擎、解码器和 GLB 均本地打包；正式定位功能不依赖 CDN。
- CDN / 第三方临时 GLB 仅作开发占位，正式发布前必须换成 `zhiteng_body3d/export` 产物，并完成许可署名。

### 资产与许可边界

- BodyParts3D 为 CC BY-SA 2.1 Japan；Z-Anatomy 主体内容为 CC BY-SA 4.0。改制后模型需保留署名、许可链接、修改说明，并按相同方式共享模型派生资产。
- Z-Anatomy 完整集中含有少量非商业或来源需单独核验的第三方结构；不得无筛选导出整套模型。
- 商业版默认只使用已确认可商用的皮肤、浅表肌肉、骨骼和必要器官；冲突结构排除，或换用 BodyParts3D 对应资产。
- 代码许可和模型数据许可分开记录；不得因参考工程代码为 MIT 就将其模型资产标为 MIT。

### 当前迁移顺序

1. 冻结 BodyParts3D / Z-Anatomy 上游版本与资产白名单，生成完整许可清单。
2. 从同一 Blender 母版生成 App / 小程序共用的2D正背视图、蒙版和映射 JSON，先替换现有简笔人体。
3. App 同时完成2D与3D：替换球体/圆柱/方块占位 `skin.glb`，本地化 Three.js 与加载器，实现场景内3D标记、深度操作、遮挡和 XYZ 持久化。
4. 小程序第一版只接入2D真实人体；现有轻量3D代码、模型和技术设计保留，但不进入首版入口和验收。
5. 小程序后续版再以现有轻量浅表肌肉为起点，加入同源低模皮肤壳，实现真正的3D深度和遮挡。
6. 首版先在 App 验证2D/3D坐标互转，并在微信、抖音真机验证2D图像、蒙版点选、局部裁切和热力图。

## 2D 到 3D 的迁移

```text
2D view + normalizedX/Y + bodyPartId
    ↓
从对应固定正交相机向 3D 人体发出 ray
    ↓
命中对应皮肤表面点，并映射 3D mesh 集合
    ↓
surface：使用表面命中点
internal_unknown：显示沿 ray 向内的可调深度轨道
unknown：只预选身体区域
    ↓
用户可在 App 3D 中进一步校准
```

只有用户在 App 3D 中完成深度校准后才保存模型空间 XYZ。不能把 2D 点直接宣传为医学精确的体内坐标。
